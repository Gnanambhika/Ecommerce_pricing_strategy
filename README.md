# E-commerce Pricing Strategy & Profitability Intelligence

An interactive analytics app that answers practical pricing questions for an e-commerce catalogue:
how profitable we are, how our prices compare with competitors, what discounting costs, how demand
responds to price, and what a price change might do to revenue and gross profit.

Built with **Python, Streamlit, Plotly, pandas, NumPy, SQLite (SQL scripts) and statsmodels**, tested
with **pytest**, and designed to deploy on **Streamlit Community Cloud**.

> **Data notice:** the bundled dataset is **synthetic**: generated by a seeded script, with fictional
> brands, products and channels. It is **not real marketplace evidence**. You can upload your own CSV
> in the app (processed in memory for your session only).

## App pages

| Page | Highlights |
|---|---|
| **Executive Overview** | KPI cards with period-over-period change, monthly revenue and margin trends, gross profit by category, data-driven observations, top-10 products (SQL window-function ranks) |
| **Pricing & Competitors** | Units-weighted price gap, share of units sold below/above competitor, performance by price band, category × channel gap heatmap, product price-positioning scatter, weekly price history for any product |
| **Discounts & Profitability** | Effective discount, discount investment, promotion vs regular weeks, discount-band volume vs margin, discount-vs-margin scatter, profit Pareto curve, lowest-margin products |
| **Demand & Elasticity** | Feasibility check (disabled for single snapshots), two-way fixed-effects elasticity per category with 95% CIs, naive slope for contrast, ground-truth check on synthetic data, binned price–demand chart, confounders and limitations |
| **Scenario Simulator** | Observed 8-week baseline, price / cost / elasticity / demand-shift inputs, simulated units, revenue, gross profit and margin vs baseline, warnings (below cost, extrapolation), break-even volume, profit curve, CI sensitivity table |
| **Data Quality & Methodology** | Validation log, field completeness, CSV import with template and messy example, data dictionary, metric definitions, the SQL behind each view |

Global filters for **date range, category, brand and platform** live in the sidebar and apply to every
analysis page. The simulator adds its own product/platform scope.

## Architecture

```
┌───────────────────────────── Streamlit app (app.py) ─────────────────────────────┐
│ st.navigation · sidebar filters · 6 pages (src/pricing_intel/ui/pages/*.py)       │
│ theme.py (CSS + Plotly template) · components.py · charts.py · state.py (caching) │
└──────────────┬───────────────────────────────────────────────┬────────────────────┘
               │                                               │
     ┌─────────▼─────────┐   ┌──────────────────┐   ┌──────────▼──────────┐
     │ db.py             │   │ metrics.py       │   │ elasticity.py       │
     │ in-memory SQLite  │   │ tested formulas  │   │ two-way FE OLS      │
     │ + sql/*.sql       │   │ (safe division)  │   │ scenario.py         │
     └─────────▲─────────┘   └────────▲─────────┘   └──────────▲──────────┘
               └──────────────┬───────┴────────────────────────┘
                     ┌────────┴─────────┐
                     │ validation.py    │◄── data_io.py ◄── CSV (sample or upload)
                     │ schema.py        │
                     └──────────────────┘
       data_generation.py ──► data/sample/synthetic_pricing_data.csv (seed 42)
```

**Key design decisions**

- **Business logic is UI-free.** Every formula, query and model lives in `src/pricing_intel/` and is unit-tested
  without a browser; pages only call it and draw the results.
- **SQL where SQL shines.** Aggregations, rankings and banding run as `.sql` files on an in-memory SQLite
  database (CTEs, JOINs to a product dimension, `CASE` bands, `RANK`/`ROW_NUMBER`/`LAG`/running `SUM` window
  functions). No database file is committed or deployed.
- **Safe filters.** Filter *structure* comes from a fixed column whitelist; every user-selected value is a bound
  SQL parameter. A test verifies an injection string is treated as data.
- **One validation path.** The bundled sample goes through the same validator as an upload.
- **No secrets.** The app calls no external services, needs no API keys, and ships a restrictive `.gitignore`.

## Dataset dictionary

One row per **date × product × platform** (weekly in the sample).

| Column | Type | Required | Description |
|---|---|---|---|
| `date` | date | Yes | Start of the trading period, `YYYY-MM-DD` |
| `product_id` | string | Yes | Stable product identifier (SKU) |
| `product_name` | string | No | Display name (defaults to `product_id`) |
| `category` | string | Yes | Merchandising category |
| `brand` | string | Yes | Brand |
| `platform` | string | Yes | Sales channel / marketplace |
| `original_price` | float | Yes | List price / MRP per unit |
| `selling_price` | float | Yes | Average transaction price per unit after discounts |
| `competitor_price` | float | No | Comparable competitor price; blank when not tracked |
| `unit_cost` | float | Yes | Landed cost per unit |
| `units_sold` | int | Yes | Units sold in the period |
| `stock_on_hand` | int | No | Units in stock at period start |
| `promo_flag` | bool | No | 1 if a planned promotion ran |

Derived per row: `revenue`, `cogs`, `gross_profit`, `gross_margin_pct`, `discount_pct`, `discount_amount`,
`competitor_gap`, `competitor_gap_pct`.

**Sample dataset:** 22,698 rows · 120 products · 6 categories · 16 brands · 3 channels · 78 weeks
(6 Jan 2025 – 29 Jun 2026) · competitor price on 87.7% of rows. Currency is INR (₹).

### Importing your own CSV

1. Open **Data Quality & Methodology** → download the **template**.
2. Export your data with one row per date × product × platform (aggregate first if needed).
3. Upload it. Common headers such as `SKU`, `MRP`, `Sale Price`, `Qty`, `Channel` are mapped automatically, and
   values like `₹1,299` are parsed.
4. Review the validation log (rows removed / repaired and why), then click **Use this dataset in the app**.

Limits: 50 MB / 500,000 rows. Data stays in memory for your browser session and is never written to disk.
Do not upload confidential data to a public deployment.

## Synthetic vs real data

| | Synthetic sample (bundled) | Your uploaded CSV |
|---|---|---|
| Source | `scripts/generate_data.py`, seed 42 | Your export |
| Brands / channels | Fictional | Real |
| Valid for real-world claims | **No** | Yes, within the stated limitations |
| True elasticities known | Yes (used to validate the method) | No |
| Labelled in the app | "Synthetic data" badge on every page | "Uploaded: <file>" badge |

The generator was designed to be useful for teaching: known per-category elasticities, seasonality, a festive
peak where promotions are deliberately more frequent (a realistic confounder), trend, cost inflation,
independent competitor promotions, tracking gaps in competitor prices, and occasional stock-outs.
No website was scraped.

## Metric definitions

Ratios are **ratios of sums**; a zero or missing denominator yields a blank, never an error or ∞.

| Metric | Definition |
|---|---|
| Revenue | Σ selling_price × units_sold |
| COGS | Σ unit_cost × units_sold |
| Gross profit | Revenue − COGS |
| Gross margin % | Gross profit ÷ Revenue |
| Average selling price | Revenue ÷ Units |
| Discount % | (original_price − selling_price) ÷ original_price |
| Effective discount rate | 1 − Revenue ÷ Σ(original_price × units) |
| Discount investment | Σ(original_price − selling_price) × units |
| Competitor price gap % | (selling_price − competitor_price) ÷ competitor_price, positive = we are pricier |
| Avg competitor gap | Units-weighted, **only** over rows with a competitor price |
| Competitor coverage | Share of units with a competitor price |
| Rankings | `RANK()` on gross profit, overall and `PARTITION BY category` |

**Excluded from profit:** shipping/fulfilment, advertising, marketplace commissions and payment fees, returns and
refunds, taxes (GST/VAT) and operating expenses. Gross margin is an upper bound on contribution margin, not net profit.

## Analytical methods

- **Elasticity:** per category, `log(units) = β·log(price) + series FE + week FE`, OLS after the within
  transformation, standard errors clustered by product×platform series. Disabled when there is a single snapshot,
  fewer than 8 periods, or too little price variation. On the synthetic data the estimates land within about 0.1 of
  the generator's true values, while the naive (no controls) slope is near zero, which illustrates why controls matter.
  These are **associations, not causal effects**; see the confounders listed in the app and in
  [docs/METHODOLOGY.md](docs/METHODOLOGY.md).
- **Simulator:** constant-elasticity demand response around an observed baseline, plus an optional non-price demand
  shift. Results are clearly labelled as simulations and include break-even volume and CI sensitivity.

## Setup (Windows PowerShell)

Requires Python 3.10–3.13 and Git. Full guide with troubleshooting: [docs/WINDOWS_SETUP.md](docs/WINDOWS_SETUP.md).

```powershell
cd "$env:USERPROFILE\OneDrive\Desktop\E-commerce"     # your project folder
$VENV = "$env:USERPROFILE\.venvs\ecom-pricing"          # kept outside OneDrive on purpose
python -m venv $VENV
& "$VENV\Scripts\python.exe" -m pip install -r requirements-dev.txt
& "$VENV\Scripts\python.exe" -m streamlit run app.py
```

## Known limitations

- The sample data is synthetic; conclusions drawn from it do not describe any real market.
- Profit is gross profit only (see exclusions above).
- Elasticity estimates do not control for advertising, on-site placement, competitor reactions, cannibalisation or
  pull-forward demand; stock-outs censor demand; zero-sales weeks are dropped.
- The simulator uses constant elasticity, holds competitors and mix constant, and is unreliable far from observed
  prices.
- Weekly grain: intra-week price changes are averaged.
- Uploaded data lives only in the browser session; there is no persistence or multi-user sharing.
- The UI uses a light theme only.

## Future improvements

- Cross-price elasticities (competitor price and sibling products) and a Poisson/PPML model that keeps zero-sales weeks.
- Hierarchical (partially pooled) elasticities per product.
- Experiment designer and analysis for controlled price tests.
